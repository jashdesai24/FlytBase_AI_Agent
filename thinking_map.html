LOGIC 02 How I Deconstructed & Thought Through The Problem
1. The Latency & Accuracy Bottleneck

Why Monolithic Prompts Fail

Asking a single large LLM prompt to research a company, analyze a contact, score a lead, and draft an email creates severe hallucination risks and massive latency. Without hard data contracts, output formatting degrades rapidly.

DECISION: Split into 7 functional micro-agents connected by strict Pydantic typed data state passed across a LangGraph pipeline.
2. Speed vs. Depth Trade-off

Parallelizing Intelligence Gather

Sequential pipeline execution results in long wait times (30+ seconds). When examining dependencies, I realized Account Research and Contact Intelligence have zero reliance on each other after normalization.

DECISION: Engineered simultaneous execution branches in LangGraph, gathering company facts & buyer seniority simultaneously.
3. The Hallucination Problem

Deterministic Scoring Core

Sales managers will not trust an AI agent that assigns random "80/100" lead scores based on prompt mood. Evaluation criteria must be absolute, verifiable, and explainable to Account Executives.

DECISION: Built Agent 4 as a 100% deterministic Python evaluation model (+25 ICP size, +20 C-Suite/VP authority, +15 corporate domain, +20 intent).
4. Personalization & Relevance

Vector Case Study RAG

Cold emails containing boilerplate praise get ignored. To generate real replies, an agent must connect a prospect's industry pain hypothesis with actual documented past customer success metrics.

DECISION: Embedded historical FlytBase drone deployment stories in ChromaDB vector store, dynamically pairing them into a 3-touch cadence.
5. User Experience & Visibility

Real-time SSE Streaming

In enterprise software, static spinning loaders cause users to assume the app has crashed during complex multi-agent reasoning loops. We needed live observability into internal agent thoughts.

DECISION: Deployed Starlette Server-Sent Events (SSE) with strict anti-buffering HTTP headers to feed live agent logs directly into the console.
6. Production Reliability

Concurrency & API Quotas

Free tier Gemini APIs enforce 15 Requests Per Minute (RPM) limits. When running parallel nodes and multiple test demos rapidly, API exhaustion causes fatal pipeline crashes without mitigation.

DECISION: Developed an automated exponential backoff engine (4s/8s/15s) with model failover (Gemini 2.5 Flash → 2.0 Flash) to absorb traffic spikes.

Interactive Component Details
Phase 1: Ingestion, Schema Normalization & Domain Validation (Agent 1) ▼

Raw leads originate from various website endpoints (pricing page, blog downloads, contact forms). Before any external APIs are invoked, Agent 1 cleans and enforces typed structures:

  • Schema Enforcement: Parses unstructured input directly into a validated LeadRecord Pydantic model.
  • Domain Classification: Extracts domain addresses and marks whether the email is corporate or generic educational/freemail (.edu, gmail.com).
  • Signal Parsing: Scans free-text form messages to extract urgency cues, use cases, and competitor references.
Phase 2: Simultaneous Parallel Web Intelligence (Agents 2 & 3) ▼

To minimize latency without sacrificing analytical rigor, LangGraph forks execution into two concurrent processing tracks:

  • Agent 2 (Account Research): Fires live web search queries via Tavily API to identify employee count, enterprise industry classification, active hardware ecosystem, and strategic corporate initiatives/news.
  • Agent 3 (Contact Persona Matrix): Classifies buyer job titles into standardized hierarchy levels (C_SUITE, VP, DIRECTOR, IC), evaluating strategic budgetary decision authority.
Phase 3: Deterministic Lead Scoring & Conditional Branching (Agent 4) ▼

Both parallel intelligence streams converge into the deterministic evaluation engine. This removes AI subjectivity:

  • Rule-Based Point Matrix: Evaluates data against strict rules: Enterprise size (>10k emps = +25 pts), Seniority (C-Suite/VP = +20 pts), Verified Corporate Email (+15 pts), and High Intent Mentions (+20 pts).
  • Conditional Edge Routing (should_nurture_or_advance): Leads scoring ≥ 40 points (Grade A & B) route forward into active sales sequence generation. Leads scoring < 40 points (Grade C & D) break out immediately into automated marketing Nurture sequences, saving valuable AE follow-up time.
Phase 4: Case Study RAG & Multi-Touch Outbound Cadence (Agents 5, 6 & 7) ▼

For qualified opportunities, the final phase prepares a comprehensive sales-ready operational package:

  • Agent 5 (Vector Retrieval): Performs semantic matching over knowledge/case_studies.json via ChromaDB, pulling exact customer reference stories matching the prospect's operational sector.
  • Agent 6 (GTM Email Engine): Synthesizes intelligence and case studies into a high-converting 3-touch outbound sequence: (Touch 1: Initial Value & Pain Hypothesis, Touch 2: Statistical Case Study Proof, Touch 3: Executive Follow-up).
  • Agent 7 (AE Handoff Brief): Summarizes the complete lead record, firmographic profile, qualification audit trail, and drafted sequences into an actionable briefing package for Account Executives.
